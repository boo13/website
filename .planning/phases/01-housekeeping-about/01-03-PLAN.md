  <name>Task 1: Implement scrub-linked grid zoom-out animation on Slide 1</name>
  <files>
    src/sections/about-slides.js
    src/styles/about-slides.css
  </files>
  <action>
  In `src/sections/about-slides.js`, within the existing `gsap.context()` callback, add the grid zoom-out animation for Slide 1:

  1. **Query elements:**
     ```javascript
     const slideGoesBig = section.querySelector('.slide-goes-big');
     const gridContainer = slideGoesBig?.querySelector('.grid-container');
     ```

  2. **Set initial state — zoomed IN to center image:**
     ```javascript
     gsap.set(gridContainer, {
       scale: 3,
       transformOrigin: 'center center',
     });
     ```
     This means the grid (already 175% of viewport via CSS) at 3x scale shows only the center image filling the screen. As it zooms out to scale: 1, the full oversized grid is revealed.

  3. **Create scrub-linked timeline:**
     ```javascript
     const gridTl = gsap.timeline({ paused: true });

     gridTl.to(gridContainer, {
       scale: 1,
       duration: 1,
       ease: 'none',  // Linear for scrub control
     });

     ScrollTrigger.create({
       trigger: slideGoesBig,
       start: 'top top',
       end: '+=150%',        // Scroll distance = 1.5x viewport height
       scrub: 1.5,           // 1.5s smooth catch-up delay
       pin: true,
       animation: gridTl,
       invalidateOnRefresh: true,
     });
     ```

  4. **Ensure slide content stays centered during pin.** The text overlay (.slide-content) should remain visible and centered throughout the zoom. It doesn't animate with the grid — it sits on top at z-index: 2.

  5. **CSS adjustments** in `src/styles/about-slides.css`:
     - Ensure `.slide-goes-big` has `overflow: hidden` (should already be set but verify)
     - Ensure `.grid-container` has `will-change: transform;` for GPU compositing
     - Ensure no parent of `.grid-container` clips overflow inadvertently (the slide itself should clip, but the grid-container's parent `.slide-bg` should not)
     - Add `.slide-goes-big .slide-content` z-index and pointer-events as needed

  IMPORTANT PITFALLS TO AVOID:
  - Do NOT set ease on scrubbed animations (ease: 'none' is correct)
  - Use `invalidateOnRefresh: true` to handle resize/orientation changes
  - The grid at scale: 1 should STILL be larger than the viewport (because CSS sizes it at 175%). At scale: 3 it should show roughly one grid cell. Test that the math works: 175% * 3 = 525% of viewport, centered. Each cell of a 3x3 grid at 525% = ~58% of viewport per cell. The center cell fills ~58% of viewport — close enough to filling the screen. If it doesn't fill enough, increase either CSS grid size (to 200%) or initial scale (to 3.5).
  </action>
  <verify>
  Run `npm run dev` and scroll to Slide 1. The background should start showing a single zoomed-in image. As you scroll, it smoothly zooms out to reveal the full 3x3 grid that extends beyond viewport edges. The slide should stay pinned (doesn't scroll away) during the animation. Text overlay should remain visible throughout.
  </verify>
  <done>Grid zoom-out animation is scrub-linked to scroll, starts zoomed in on center image, reveals full oversized grid, slide is pinned during animation, and invalidateOnRefresh handles resize.</done>
