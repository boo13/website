# Particle Portrait — About Section Hero

**Date:** 2026-03-01
**Status:** Design approved

## Goal

Add a scroll-driven particle portrait effect to the about section of index.html. A crisp photo with tagline text dissolves into a 3D particle system as the user scrolls, then scatters and fades out — a one-way disintegration that transitions into the About Intro section.

## Page placement

Inserted as a new section between Hero and About Intro:

```
Hero → [About Portrait (new)] → About Intro → About Slides → Featured Work → ...
```

## Resting state

- Crisp `<img>` of RandyHeroPic.JPG, centered
- Short tagline text overlaid on the image
- Three.js `<canvas>` renders the particle system behind the image, invisible (opacity 0)
- Particles are pre-built and positioned to align with the photo

## Scroll timeline (one-way, scrub-driven)

| Phase | Scroll % | What happens |
|-------|----------|-------------|
| 1 | 0–10% | Tagline mask-wipes out (sharp horizontal clip edge) |
| 2 | 5–25% | Photo `<img>` fades to transparent, flat particle grid visible |
| 3 | 20–50% | Depth displacement ramps up (particles push in Z via depth map) |
| 4 | 45–70% | Camera shifts to side angle, revealing 3D layering |
| 5 | 65–90% | Particles scatter outward and fade |
| 6 | 90–100% | Section ends, About Intro scrolls in naturally |

No reform, no return to photo. The portrait disintegrates once.

## Architecture: Dual-layer (DOM + WebGL)

- **DOM layer (on top):** `<img>` + tagline text, animated by GSAP (opacity, clip-path)
- **WebGL layer (behind):** Three.js canvas with particle system, driven by GSAP ScrollTrigger uniforms
- Both layers coordinated by a single ScrollTrigger scrub timeline

This avoids the need for photo rendering in WebGL. The `<img>` is genuinely crisp. The particle system pre-warms behind it.

## Transition alignment

The particle grid must visually align with the photo. Particles are positioned using viewport-relative sizing (same FOV/distance calculation as the photo's CSS layout). The photo's DOM position and the canvas camera are calibrated so the crossfade is seamless.

## Depth map generation

One-time offline script using Depth Anything v2 (PyTorch):

```
scripts/generate-depth-map.py
```

Install: `pip install torch torchvision depth-anything-v2` (or equivalent).
Run once, check in the resulting PNG. Not part of the build pipeline.

The current PLY-derived depth map is misaligned because it rasterizes 3D point cloud coordinates without proper camera projection. ML monocular depth estimation produces pixel-aligned depth maps by definition — the model takes the 2D image as input.

## Performance

- Three.js always loaded (user chose simplicity over lazy-init)
- Particle count: ~270K (640×427 grid, sampling every 2px from 1280×853 source)
- Single draw call (Points geometry)
- Canvas rendering paused when section is not near viewport (ScrollTrigger callbacks)
- Target: 60fps on desktop

## Existing sandbox files
