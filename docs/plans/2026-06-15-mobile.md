# Unified Responsive Baseline System

## Context

The site has good responsive bones on the homepage (fluid `clamp()` type, 6-col grid tokens, OKLCH colors) but no shared system: project pages use a different layout (1600px flex, hardcoded px type like `91px` titles that don't scale), contact duplicates tokens with its own grid-collapse rules, breakpoint values live in CSS literals with only 2 constants in `config.js`, and JS viewport checks are inconsistent (`< 768` vs `<= 768`, hardcoded `(max-width: 480px)`). Goal: one canonical breakpoint set, one shared token layer, one visual grid across homepage, project pages, and contact — so mobile/tablet work well and every section aligns to the same grid.

**User decisions (locked):** scope = homepage + project pages + contact (defer portfolio, resume, aiplaylists, medialog, wyatt, legacy). Project pages move FULLY onto the homepage grid (1400px / 6-col). All px type tiers → fluid `clamp()`. Before/after visual audit.

**Verified facts that shape the plan:**
- In-scope CSS already uses only 480/768/1024(/1025) — canonicalization is codification, not migration. The scattered 520/560/600/860/980 breakpoints are all in deferred files.
- `about-intro.css`/`about-slides.css` referenced by CLAUDE.md/DESIGN.md **do not exist**; homepage CSS = `index.css`, `hero-aperture-dual.css`, `video-lightbox.css` (imported from `src/main.js`).
- `scripts/capture-visual-audit.js` is broken: it scrolls to `.about-intro-section`, `.slide-goes-big`, `.slide-in-your-hand`, `#credits`, `#clients` — none exist in current `index.html` — and it hardcodes `BASE_URL = "http://localhost:5173/"` (homepage only). Current homepage sections are `#hero`, `#featured`, `#work`, `#cta`, `#site-footer` (footer is an ID now, not `.site-footer`). Must be made route-aware AND given current selectors before the baseline, or project/contact pages can't be captured.
- Project page templates (re-verified, unchanged): `projects/upnext-news/` is the editorial **case-study** template (exercises `case-study.css`); `sitting-bull`, `wyatt-earp`, `pope`, `men-who-built-america` are **video** projects (`project.css`). All use `src/main-project.js`, which loads both stylesheets. `project-case-study.js` confirmed ScrollTrigger-only (no Flip, no pins, no width-measuring) → 1600→1400 is CSS-only risk.
- `index.html:114` has an inline `@media (max-width: 480px)` in the critical preloader CSS — must be treated as a governed exception (kept in sync by hand, noted in DESIGN.md).
- **DESIGN.md has grown since this plan was first written:** it now already contains a "Project Page Type Scale" px-tier table (DESIGN.md ~262), a "Layout → Responsive Breakpoints" section with *Homepage* and *Project Pages* breakpoint tables (~319–341), and a "Project Pages" layout note that hardcodes "No CSS grid system. The scope line (DESIGN.md:103) still says the doc "Does not govern utility pages (contact, resume)" — contact consumes the shared tokens but stays outside DESIGN's prescriptive scope; do not imply contact is fully governed.
- `config.js` currently exports `CDN_BASE`, `MOBILE_BREAKPOINT`, `GALLERY_BREAKPOINT`, `SCRUB`, `TRAIL_K/MAX_PX/THRESH/OPACITY`. The new `BREAKPOINTS`/`GALLERY_SCROLL_BUFFER` are **added alongside** these; only `MOBILE_BREAKPOINT`/`GALLERY_BREAKPOINT` are retired.
- No PostCSS config exists → no custom-media; use a documented convention instead (no new deps).
- No GSAP width-measuring risk on project pages (`project-case-study.js` uses trigger-relative/scale/yPercent only; no Flip, no pins). The 1600→1400 change is CSS-only risk.
- `playwright-cli` and `just` are NOT installed in this environment — set up playwright-cli per the repo's verification rules and run the audit recipe's steps manually.

## 1. Canonical breakpoints (single source of truth)

`src/config.js`:
```js
export const BREAKPOINTS = Object.freeze({
  mobile: 480,   // phone portrait
  tablet: 768,   // phone landscape / small tablet
  desktop: 1024, // tablet/desktop seam — pairs with min-width: 1025px
});
export const GALLERY_SCROLL_BUFFER = 200; // px past track end on pinned horizontal gallery
```
Retire `MOBILE_BREAKPOINT`/`GALLERY_BREAKPOINT` (importers: `gallery.js`, `featured-work.js`).

**Direction convention (codifies what index.css already does):** "down" = `max-width: N`; "up" = `min-width: N+1` (so `max-width: 1024px` pairs with `min-width: 1025px` — resolves the off-by-one). JS mirrors the small side: `innerWidth <= BP`.

**CSS sync:** mandatory comment header in `tokens.css` + DESIGN.md rule that no other media-query widths may appear in governed files. Audit check: `rg -o '@media[^{]*' src/styles index.html` — every width must be 480/768/1024/1025. **Explicit exception:** the inline critical preloader CSS in `index.html` (line ~114) keeps its hand-synced `(max-width: 480px)`; note it in DESIGN.md.

(Line numbers re-verified; treat as approximate — match on selector, not line.)
- **Type families:** `--ff-display`, `--ff-body` (project.css's `--project-font-body/display` are renamed to these — same values).
- **Grid:** `--grid-columns: 6`, `--grid-gutter: 20px`, `--grid-max-width: 1400px`, `--grid-edge-offset` (formula from index.css:47).
- **Spacing:** `--container-padding: clamp(1.5rem, 5vw, 4rem)`, `--section-padding: clamp(4rem, 10vh, 8rem)`.
- **Motion:** `--dur-*`, `--ease-out-expo`, `--ease-in-out-circ`.
- **Responsive grid collapse (the uniform system):**
  ```css
  @media (max-width: 768px) { :root { --grid-columns: 4; } }
  @media (max-width: 480px) { :root { --grid-columns: 2; --grid-gutter: 14px; --container-padding: 1.25rem; } }
  ```
- Page-scoped tokens stay local (`--hero-social-*`, credits-section vars, contact pill-nav vars).

Then delete the duplicated `:root` blocks from `index.css`, `contact.css`, `project.css`.

## 4. Project page grid migration (`src/styles/project.css`, `case-study.css`)

- `.project-credits__wrapper` (project.css:229): flex/1600px → `display: grid; grid-template-columns: repeat(var(--grid-columns), minmax(0,1fr)); gap: 0 var(--grid-gutter); max-width: var(--grid-max-width); padding: var(--space-credits-top) var(--container-padding) var(--space-credits-bottom);`
- `.project-credits__text` → `grid-column: 1 / 5`; `.project-credits__image` → `grid-column: 5 / 7`, drop fixed 460px/340px widths; poster img `height: 615px` → `aspect-ratio: 3 / 4` (preserves current proportions). **Accepted visual change:** poster ≈411×548 @1440 (vs 460×615), ≈280px wide @1024 (vs 340).
- ≤768: both blocks `grid-column: 1 / -1` (replaces `flex-direction: column`); delete now-redundant ≤1024 width overrides and px type tiers.
- `.project-footer`: `max-width: var(--grid-max-width); padding: 40px var(--container-padding)`.
- Hero video UI insets (`__bottom`/`__close`/`__sound-btn`, 21/20/16px): keep a dedicated `--hero-ui-inset: clamp(1rem, 2vw, 1.5rem)` rather than `--container-padding` (full-bleed player controls shouldn't drift 64px inboard) — review against after-screenshots.
- `case-study.css`: side padding 40/24/16px → `var(--container-padding)` (delete the two media-query padding blocks); grid max-widths 1600px → `var(--grid-max-width)`; normalize px-in-clamp to rem (same values).
- **Sanctioned exception (document in DESIGN.md, do not migrate):** the case-study internal image grids (`__pair-grid` 2-col, `__triptych-grid` 3-col, asymmetric grid, 8px gaps) stay as magazine layouts. They align to the visual grid at their outer edges (shared max-width + container padding) but their internal columns are editorial composition, not the 6-col system. Migrating them to 6-col spans would redesign the layouts — out of scope.
