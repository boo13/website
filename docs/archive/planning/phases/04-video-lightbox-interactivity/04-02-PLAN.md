  <action>
    Refactor the existing `setupVideoHover()` function in `src/sections/gallery.js`:

    1. Add mobile/touch detection at the top of the function:
       ```javascript
       const isTouchDevice = 'ontouchstart' in window || navigator.maxTouchPoints > 0;
       if (isTouchDevice) return; // No hover previews on touch devices
       ```

    2. Replace the immediate play() on mouseenter with a 200ms hover intent delay:
       ```javascript
       let hoverTimeout = null;

       card.addEventListener('mouseenter', () => {
         hoverTimeout = setTimeout(() => {
           if (video.readyState === 0) {
             video.load(); // Lazy load if not yet loaded
           }
           video.play().catch(() => {});
         }, 200);
       });

       card.addEventListener('mouseleave', () => {
         clearTimeout(hoverTimeout);
         video.pause();
         video.currentTime = 0;
       });
       ```

    3. The 200ms delay prevents:
       - Videos loading during fast horizontal scroll (user scrolls through cards quickly)
       - Unnecessary network requests when cursor briefly passes over cards
       - Performance hits from multiple simultaneous video.play() calls

    4. Keep `preload="none"` on video elements in HTML (already set). The `video.load()` call on hover intent handles lazy loading.

    5. Do NOT change the existing reduced-motion or mobile layout fallback code at the top of `initGallery()` (lines 52-62). That code handles the structural layout change for mobile/reduced-motion. The touch detection here is specifically for the hover video behavior.

    6. Do NOT modify the ScrollTrigger setup, horizontal scroll behavior, or progress indicator logic.
  </action>
